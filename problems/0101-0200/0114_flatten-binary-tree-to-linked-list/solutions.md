# Solutions — Flatten Binary Tree to Linked List

## In-place pre-order splice

The flattened list is just the pre-order traversal strung along `right` pointers, so nothing needs to be rebuilt — only relinked. For a node with a left child, the last node visited before its old right subtree in pre-order is the rightmost node of the left subtree: a pre-order walk enters the left subtree, exhausts it, and only then takes the right subtree, and the rightmost node is where that exhaustion ends. So the splice is three pointer writes: the left subtree's tail adopts the old right subtree, the left subtree swings across to the right, and the left pointer is nulled. After that the cursor steps onto what is now `node.right` — the old left subtree's root, the next node in pre-order — and every node it has already passed sits on a single right spine, the finished prefix of the list.

The walk is a plain loop: one cursor down the spine, plus a short inner hunt for each left subtree's tail. Each edge is traversed at most twice — once by the cursor, at most once during a tail hunt, because a hunted right spine is spliced onto the finished prefix and never hunted again — and no recursion and no auxiliary stack exist anywhere. That last part is deliberate: the tempting alternative, a reverse-preorder recursion carrying the growing tail, is only three lines shorter, but a skewed 2000-node chain would recurse 2000 frames deep, past CPython's default limit of 1000, while the loop has no depth to overflow at all. The follow-up asks for O(1) extra space and this shape delivers it as a side effect — it is the Morris connection, minus even the temporary threading, since the judge only ever sees the final spine.

Nodes are only ever relinked, never allocated, so the tree is flattened in place and the very same `root` handle — now the head of the list — is returned to the judge, matching this judge's contract that it observes the return value rather than the mutated argument. Rust's nodes are owned `Box`es rather than shared pointers, so there each splice takes the two children out with `take` and hands them to their new parents; the pointer writes become ownership moves, but the algorithm is the identical splice in every one of the seven languages.

**Complexity:** `O(n)` time — each node is visited once by the cursor and each edge walked at most twice — and `O(1)` extra space.
