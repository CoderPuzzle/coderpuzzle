# Solutions — Painting a Grid With Three Different Colors

## Column-State Dynamic Programming

The grid is at most 5 rows tall but up to 1000 columns wide, so the efficient axis to enumerate is the column, not the cell. Every valid coloring of a single column (vertically adjacent rows differing) is one state — at most 3·2^(m-1) = 48 of them, generated by `itertools.product` over three colors and filtered for adjacent equality. Two columns may sit next to each other exactly when they differ in every row, so the whole problem becomes a path-counting DP over the `n` columns of a small state graph.

Transitions are precomputed once: for each state `i`, `compat[i]` lists the states differing from it row by row. The DP then keeps a vector `cur` with one entry per state — initially all ones, since the first column can take any valid coloring — and for each of the remaining `n - 1` columns scatters every state's count to its compatible successors, taking results modulo 10^9+7. The final answer is the sum of the vector, because the last column may end in any state. States with zero count are skipped in the inner loop, a small constant-factor saving.

Starting from all-ones rather than running a first transition makes `n = 1` fall out with the loop body never executing: the answer is just the number of valid single-column colorings (3 for `m = 1`, matching the first example). With `S` states the compatibility table costs `O(S^2·m)` to build and each column costs at most `O(S^2)` transitions, trivial for `S <= 48` and `n <= 1000`.

**Complexity:** `O((n + m)·S^2)` time where `S = 3·2^(m-1) <= 48`, `O(S^2)` space.
