# Solutions — Confusing Number II

## Backtrack over the valid digits with an incremental rotation

A confusing number must use only the five rotatable digits, so every
candidate can be generated by a depth-first search that appends digits
from `{0, 1, 6, 8, 9}` (never a leading zero) and prunes once the value
exceeds `n`. The depth is at most the digit length of `n` — ten for
`n = 10⁹` — so the recursion visits exactly the valid-digit numbers up
to `n`, at most a couple of million for the largest input.

Rotating a candidate is not recomputed from scratch per node. As a digit
`d` is appended to a value `cur` with `k` digits, the rotated value of
the new number is `rot180(d) * 10^k` plus the already-tracked rotated
value of `cur`: appending a digit moves every old digit one place left
in the reversed, mapped digit sequence. Carrying `(cur, rotated,
digits)` down the recursion turns the rotation test into `O(1)` per
candidate, and a candidate is confusing exactly when `rotated != cur`.

**Complexity:** `O(V)` time and `O(L)` recursion space, where `V` is the
number of valid-digit integers in `[1, n]` (at most `5¹⁰`) and `L <= 10`
is the digit length of `n`.
