# Solutions — Digit Operations to Make Two Integers Equal

Treat every value `n` can take as a graph node. A single digit operation
moves between two values, the digit count never changes (a leading 1 may
not drop to 0), and only non-prime values may be visited — so the graph
has fewer than `10⁴` nodes with at most eight moves out of each, and the
answer is a shortest-path question from `n` to `m`.

## Sieve + Dijkstra over digit states

A sieve of Eratosthenes to `10⁴` marks the composites, and the weight of
a move is the value arrived at, with the starting value as the initial
cost — that is exactly "the sum of all values that `n` takes", original
included: the example path `10 → 20 → 21 → 22 → 12` costs
`10+20+21+22+12 = 85`. With non-negative weights a min-heap Dijkstra
settles each state once; every neighbor generated by a ±1 on one digit
that lands on a composite gets a relaxation attempt, and popping `m`
returns the answer. If `n` or `m` is itself prime (or the heap empties)
the transformation is impossible and the result is `-1`.

Neighbors come from place-value arithmetic — add or subtract `10^k` when
the `k`-th digit allows it, skipping the leading 1 → 0 decrement — so no
string rebuilding is needed. Costs are bounded by one visit per state
times the largest value, under `10⁸`, comfortably inside 32-bit range.

**Complexity:** `O(V log V + E)` time with `V < 10^4` states and `E ≤ 8V`
moves (plus the `O(V log log V)` sieve), `O(V)` space.
