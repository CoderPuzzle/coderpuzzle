# Solutions — Closest Subsequence Sum

## Meet in the Middle

With `n` up to 40, enumerating all 2^40 subsequences is hopeless, but splitting the array into two halves of at most 20 elements makes each side enumerable at about 10^6 sums. Every subsequence of the whole array is the disjoint union of a left-half part and a right-half part, so its sum is `sL + sR`; being close to `goal` for the pair is the same as `sL` being close to `goal - sR`. That reduces the search to: enumerate all subset sums of one half, sort them, and for each subset sum `s` of the other half binary-search the sorted list for the values bracketing `goal - s`.

Subset sums are generated by doubling: starting from `[0]`, each element `v` extends the current list with a copy of itself shifted by `v`, so a list of `t` sums becomes `2t`. The left half's list is sorted once; the right half's list stays unsorted since it only serves as the query side. For each right sum `s`, `bisect_left` locates the insertion point of `need = goal - s`, and only the two neighbors `idx - 1` and `idx` — the floor and ceiling candidates — can minimize `abs(left[j] + s - goal)`; both are checked and the best difference is kept.

The empty subsequence is covered because both lists contain 0, and `best` starts as `None` so the first valid pair always initializes it. Comparing only the two bracketing values is complete: any other left sum lies strictly outside the interval they span and is therefore farther from `need`.

**Complexity:** `O(2^(n/2) n)` time, `O(2^(n/2))` space.
